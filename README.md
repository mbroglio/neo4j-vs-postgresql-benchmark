## 🎯 Project Overview

Graph database engines (like Neo4j) claim superior performance over relational systems when executing complex multi-hop graph traversals, thanks to **Index-Free Adjacency (IFA)**. In contrast, relational databases (like PostgreSQL) rely on B-Tree indexes, multi-table `JOIN` operations, and recursive Common Table Expressions (`WITH RECURSIVE`).

This benchmark laboratory evaluates both engines under identical synthetic workloads generated by the **LDBC Social Network Benchmark (SNB)** data generator across multiple Scale Factors (e.g., `SF 0.1` and `SF 1`).

### Evaluated Metrics
- **Query Execution Latency** (mean, median, 95th/99th percentiles)
- **RAM and CPU Footprint** (dynamic memory scaling during deep traversals)
- **Execution Plans** (`EXPLAIN` / `PROFILE` in Cypher vs. `EXPLAIN ANALYZE` in SQL)
- **Transaction & Concurrency Behavior** (write amplification, row/node locking, WAL overhead)

## ⚖️ Architectural Paradigm Comparison

| Dimension | Neo4j (Graph DBMS) | PostgreSQL (Relational DBMS) |
| :--- | :--- | :--- |
| **Data Model** | Labeled Property Graph (Nodes, Relationships, Properties) | Relational Tables (Rows, Foreign Keys, Join Tables) |
| **Query Language** | Cypher | SQL (with CTEs & Window Functions) |
| **Traversal Mechanism** | **Index-Free Adjacency (IFA)**: Direct pointer dereferencing ($O(1)$ per edge) | **Index Lookups & Joins**: Hash / Merge / Nested Loop joins ($O(\log N)$ or table scans) |
| **Deep Graph Hops (k ≥ 3)** | Execution time proportional to subgraph size | Exponential growth in intermediate join table size |
| **Tabular Aggregation** | Moderate efficiency | Highly optimized vectorized/parallel aggregate engines |

## 🧪 Benchmark Scenarios

The suite includes four distinct experimental evaluation scenarios located in `benchmark-lab/benchmarks/`:

1. **Scenario 1: K-Hop Graph Traversals & Memory Profiling**
   - Evaluates multi-hop friend-of-a-friend traversals ($k \in \{1, 2, 3, 4\}$).
   - Measures RAM consumption peaks during deep traversals (`ram_profiler.py`).
   - Compares Cypher variable-length paths (`(p:Person)-[:KNOWS*k]->(f:Person)`) with recursive SQL CTEs.
2. **Scenario 2: Concurrent Read/Write & Transaction Isolation**
   - Evaluates system throughput under mixed read/write workloads.
   - Evaluates lock contention, concurrency limits, and Write-Ahead Logging (WAL) amplification.
3. **Scenario 3: Complex Social Network Analytics**
   - Runs LDBC SNB Interactive Complex queries involving pattern matching, multi-criteria filtering, and ranking.
4. **Scenario 4: Scalability Across Scale Factors**
   - Analyzes degradation curves when scaling from `SF 0.1` (~100MB) to `SF 1` (~1GB raw graph data).

## 🚀 Quick Start: Reproducing Benchmarks

### Prerequisites
- Ubuntu 20.04 / 22.04 LTS (or compatible Linux)
- Docker & Docker Compose (`docker compose version >= 2.0`)
- Python 3.10+
- GNU Make

### 1. Infrastructure Provisioning
Navigate to the infrastructure directory, install requirements, generate synthetic LDBC SNB data, and initialize the databases (`SF=0.1` or `SF=1`):

```bash
cd benchmark-lab/infrastructure

# 1. Install prerequisites and LDBC SNB data generator tools
make setup

# 2. Generate synthetic data at Scale Factor 0.1
make generate SF=0.1

# 3. Ingest and index data into Neo4j and PostgreSQL
make build SF=0.1

# 4. Spin up the containers
make up SF=0.1
```

### 2. Running Benchmarks
Once the containers are running and healthy:

```bash
cd ../benchmarks

# Run system profiling & query benchmarks
python3 system_profiler.py

# Or run specific scenario suites:
cd scenario1 && python3 scenario1_benchmark.py
```

### 3. Environment Cleanup
To tear down containers and clear database volumes while preserving raw CSV files:

```bash
cd ../infrastructure
make clean
```
